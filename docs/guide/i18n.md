# 国际化

读完你知道文案放在哪里、如何新增翻译、错误码如何翻译，以及如何避免硬编码。

## 支持语言

| code | 名称 | 默认 |
|---|---|---|
| `zh-CN` | 简体中文 | 是 |
| `en-US` | English | 否 |

`nuxt.config.ts`：

```ts
i18n: {
    strategy: 'no_prefix',
    defaultLocale: 'zh-CN',
    langDir: '../i18n/locales',
    locales: [
        { code: 'zh-CN', language: 'zh-CN', name: '简体中文', file: 'zh-CN.json' },
        { code: 'en-US', language: 'en-US', name: 'English', file: 'en-US.json' },
    ],
    detectBrowserLanguage: {
        useCookie: true,
        cookieKey: 'picturex.lang',
        redirectOn: 'root',
    },
}
```

`srcDir` 是 `app/`，因此 `langDir` 回退一级指向 `apps/web/i18n/locales/`。

## 切换语言

入口只有一个：「设置 → 语言」（`/settings/language`）。框架侧边栏不放语言下拉，
底部只保留主题切换，避免把用户内容区和全局操作混在一起。

`useLocale().switchLocale(code)`：

1. `setLocale(code)` 即时切换 vue-i18n。
2. 写 cookie `picturex.lang` 与 `localStorage['picturex.lang']`。
3. `PATCH /settings` 持久化 `i18n.defaultLocale`。
4. `ConfigProvider.locale` 随 `useI18n().locale` 同步，分页/日期等组件文案一起变化。

服务端 SSR 按 cookie > `Accept-Language` > 默认语言决定首屏，`<html lang>` 随之渲染。

## 文案目录

```
apps/web/i18n/locales/zh-CN.json
apps/web/i18n/locales/en-US.json
```

命名空间：

| 命名空间 | 内容 |
|---|---|
| `common` | 通用按钮、状态、单位 |
| `nav` | 侧边导航与主题切换 |
| `album` | 相册页面 |
| `asset` | 查看器、EXIF、标签 |
| `settings` | 设置页 |
| `jobs` | 任务页 |
| `models` | 模型管理 |
| `theme` | 外观与 Token 名称 |
| `viewer` | 桌面「打开方式」查看器 |
| `library` | 全局图库与全局标签 |
| `pixivLibrary` | Pixiv 资料库 |
| `errors` | 错误码翻译（键名 = `ApiError.code`） |
| `a11y` | 图标按钮、图片 alt、区域标签 |
| `home` | 首页特性文案 |
| `picker` | 目录/封面选择器 |

共 15 个命名空间。

新增文案：

```json
{
    "album": {
        "storageWarning": "磁盘空间不足"
    }
}
```

两个 locale 必须同时添加；使用 `t('album.storageWarning')`。

## 错误码翻译

服务端只返回稳定 `code` 与英文 `message`：

```ts
throw new ApiError(404, 'album_not_found', 'The requested album does not exist.');
```

`useApi()` 在 hc 的 `fetch` 选项中拦截 `application/problem+json`：

```
errors.<code> → detail → message
```

开发模式缺失翻译会 `console.warn`，生产静默回退。校验：

```bash
pnpm check:i18n
```

脚本会扫描 `server/**` 中所有 `ApiError(...)` 与 `sendProblem(...)` 的字面量 code，
与两个 locale 的 `errors.*` 对比，缺失即失败。

## 格式化

`useFormat()` 封装 `Intl.*`：

```ts
const { formatDate, formatDateTime, formatRelative, formatBytes, formatDuration, formatPercent } = useFormat();
```

不要在组件里直接 `new Intl.DateTimeFormat` 或引入 dayjs。

## 无障碍

所有图标按钮、图片 `alt`、区域标签使用 `a11y.*` 命名空间；用户内容（文件名、相册名、标签）不翻译。
AntdvNext 的 `ConfigProvider.locale` 只影响组件内部文案（分页、空状态等），业务文案仍走 `t()`。

## 硬编码审计

```bash
pnpm check:hardcode
```

该门禁扫描 `app/**/*.{vue,ts}` 的用户可见中文与十六进制色值；只允许命中注释
（以及测试中的 a11y 数据）。`.vue` 中不得出现中英文用户文案；
`docs/` 不在此约束内。
